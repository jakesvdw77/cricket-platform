League page: the proposed standard anatomy

Starting with the league view. The same four rules would then apply to every page. This is a proposal for you to judge; heights below are the Matches counter card's, to be taken exactly from PageCounters when built.

The four rules
  1. One figure card: the Matches counter card. Raised, one fixed height (44 px), the number then its label on one line, no icon, no "FILTER" tag. A card you can click (a counter that filters) shows a pointer cursor and a small lift on hover, and a green ring when selected. A static figure is the same card without the pointer.
  2. One filter bar: flat. Search, selects and switches on a single row on the page wash (no box). The segmented toggle sits in that row too.
  3. One header: Back and the page-level actions on the top row (Actions menu, Edit); title with its badges and the Season pill beside it; contacts directly under the title; then figures, tabs (with the tab's actions on the tab row), the filter bar, and the data.
  4. Raised only where it holds content: figure cards, tables and panels are raised; controls (filter bar, toolbars) are flat. Counts live in the table header, never repeated above it.

Schedule tab, desktop

Compare with the Matches page: the figure cards are the same card. On the league page the first and third are static (no click), the age reference is an info icon in its card.

What changes versus today

1. The league page's figure row uses the Matches card (no icon, 44 px, raised), replacing the icon tiles and my strip. 2. The filter bar is flat here and, once agreed, on every page. 3. "FILTER" tags disappear everywhere; clickable counters rely on the pointer cursor, hover lift and the selected ring. 4. The header pattern is identical on every detail page. 5. A static figure and a clickable counter are the same component with one optional prop.
