Import framework: wizard screens

Spec 097. Three new patterns for approval: the Validate step (issue table), the Resolve step (reference resolver, also used for "Identify what is ours") and the Review and confirm step. Shown at desktop and 375 px. The sample is a league schedule import (the first consumer, 098), but the screens are generic. Buttons are 32 px (44 px on a phone), status is always an icon-style chip plus a word, never colour alone.

1. Validate: issue table

Counters double as filters (Warnings and Errors). "Problems only" switch sends the filter to the server. A fourth neutral chip, "Skipped, not ours", is not a problem and never blocks. Each row has Exclude or Include. The skipped rows sit in an expandable section.

2. Resolve: reference resolver

One card per distinct unrecognised name, with ranked proposals (confidence and reasons). Nothing is preselected except an exact match or an alias you already confirmed once (still shown, still counted). Creating is only chosen here and confirmed on the Review step. The same component renders "Identify what is ours".

3. Review and confirm

Everything that will be created is listed, nothing has been saved yet and the page says so. Warnings are grouped by kind, each with one tick. Confirm stays disabled, with the reason beside it, until there are no errors and every warning is ticked. On a phone the Confirm button is full width and sticky.

Notes for approval

Step names above (Check rows, Identify ours, Match teams, Review) are plain-English labels for the spec's Validate and Resolve steps; "Identify ours" only shows in Ours-only mode. The report step, the history panel and the upload step reuse existing patterns (key figure tiles, side panel, the results import's upload and "convert with AI" help) and are not redrawn here.
