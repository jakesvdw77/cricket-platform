# Plan: 053 — League Extended Profile

## Context

`docs/specs/053-league-extended-profile.md` (approved) gives `League` the same club-facing profile shape `ClubProfile`/`Sponsor` already have: a logo, a purely cosmetic `format` tag, phone/website/email, and social links. This is the first of three sibling specs (053/054/055) extending `League` in parallel; this plan covers 053 only. Every shape (entity fields, enum values, DTO/request fields, component composition) is already fixed by the spec, verified against the real current source in this session — this plan sequences the work and confirms exact insertion points.

**Verified directly against current source this session** (not just the spec's own claims): `League.java`, `LeagueDto`/`CreateLeagueRequest`/`UpdateLeagueRequest`, `LeagueMapper`, `LeagueServiceImpl` (including the `withCurrentSeasonFields` positional-reconstruction gotcha the spec flags — confirmed real at `LeagueServiceImpl.java:112-115`), `SponsorMapper`/`SponsorServiceImpl`/`CreateSponsorRequest` (the exact `SocialLinkValidation`/element-mapping pattern to replicate), `SocialLinkDto`, `LeagueSource` (enum convention), `LeagueForm.tsx` (currently flat fields, no inner Tabs — confirmed it needs to grow one), `SponsorForm.tsx` (the exact Tabs/MediaUpload/WebsiteInput/SocialLinksFields composition to mirror), `MediaUpload`/`WebsiteInput`/`SocialLinksFields` component APIs, `leagueApi.ts`, `LeagueFormPage.tsx` (confirmed `LeagueForm` renders directly under `activeTab === 0`, not wrapped — the new inner-Tabs `LeagueForm` needs its own `gridColumn: '1 / -1'` wrapper, matching `SponsorForm`'s root `Box`), `LeagueList.tsx`/`RecordCard`'s `chips`/`avatar` props, `LeagueDetailPage.tsx`'s Details section (exact `DetailFieldGrid` insertion point and the `note` slot pattern already used by the Playing Conditions/Fixtures sections), `SponsorDetailPage.tsx` (exact phone/email/website/`SocialLinksRow` layout to mirror), `db.changelog-master.xml` (confirmed highest migration is `028`, so `029` is genuinely next), and confirmed the real test file paths (`LeagueServiceImplTest.java`, `LeagueControllerIntegrationTest.java`, `LeagueForm.test.tsx`, `LeagueList.test.tsx`, `LeagueDetailPage.test.tsx`, `LeagueFormPage.test.tsx` all exist and are the ones to extend).

## Files to touch, in order

### Backend (`backend-builder`)

1. **`backend/src/main/java/com/cricketlegend/domain/LeagueFormat.java`** (new enum) — `T20, T30, T45, T50, ONE_DAY, THREE_DAY, FIVE_DAY`, per spec's Data Model Changes.
2. **`backend/src/main/resources/db/changelog/v1/029-add-league-profile.sql`** (new) — exact SQL from the spec: `ALTER TABLE league ADD COLUMN` x5 (`logo_url VARCHAR(512)`, `format VARCHAR(16)`, `phone VARCHAR(32)`, `website VARCHAR(512)`, `email VARCHAR(255)`), plus `CREATE TABLE league_social_link` (composite PK `(league_id, platform)`, FK `league_id`). Register in `db.changelog-master.xml` immediately after `028`'s entry.
3. **`backend/src/main/java/com/cricketlegend/domain/League.java`** — add `logoUrl` (String), `format` (`LeagueFormat`, `@Enumerated(EnumType.STRING)`), `phone`/`website`/`email` (String), `socialLinks` (`List<SocialLink>` via `@ElementCollection`/`@CollectionTable(name = "league_social_link", joinColumns = @JoinColumn(name = "league_id"))`, `@Builder.Default new ArrayList<>()` — mirror `Sponsor.socialLinks` exactly).
4. **`backend/src/main/java/com/cricketlegend/dto/LeagueDto.java`** — add `format`/`logoUrl`/`phone`/`website`/`email`/`socialLinks` record components (position: after `ageCutoffDate`, before `active`, matching the spec's field ordering — confirm final position doesn't matter functionally but keep it consistent and update the Javadoc).
5. **`backend/src/main/java/com/cricketlegend/dto/CreateLeagueRequest.java`** / **`UpdateLeagueRequest.java`** — add the same five fields, `socialLinks` as `@Valid List<SocialLinkDto>` (mandatory `@Valid`, per `CreateSponsorRequest`'s own documented lesson about a missing annotation silently skipping nested validation).
6. **`backend/src/main/java/com/cricketlegend/mapper/LeagueMapper.java`** — add `SocialLinkDto toDto(SocialLink)` / `SocialLink toEntity(SocialLinkDto)` element-mapping pair (mirrors `SponsorMapper` exactly) so MapStruct auto-generates the `List` mapping both directions; the five scalar fields need no explicit `@Mapping` (name-inferred).
7. **`backend/src/main/java/com/cricketlegend/service/impl/LeagueServiceImpl.java`**:
   - `create()`: build the five new fields onto the `League.builder()` call (`logoUrl(request.logoUrl())`, etc.; `socialLinks` needs a small helper mirroring `SponsorServiceImpl.toSocialLinks`, since `League` is built via `.builder()` not `mapper.toEntity()`), and call `SocialLinkValidation.requireNoDuplicatePlatform(request.socialLinks())` before building.
   - `update()`: same `SocialLinkValidation` call plus the five `league.setXxx(...)` assignments, mirroring `SponsorServiceImpl.update`.
   - **`withCurrentSeasonFields`** (line ~109-116): this is the one real trap the spec calls out — its positional `new LeagueDto(...)` reconstruction must add the five new positional args in the exact same order `LeagueDto`'s canonical constructor now has them, or the build won't compile. Update deliberately, not by fighting compiler errors blind.
   - Add `import com.cricketlegend.dto.SocialLinkDto;`, `import com.cricketlegend.domain.SocialLink;`, `import com.cricketlegend.service.support.SocialLinkValidation;`, `java.util.ArrayList` as needed.
8. **`backend/openapi/openapi.yaml`** — hand-edit (established convention) to document the five new fields on `LeagueDto`/`CreateLeagueRequest`/`UpdateLeagueRequest`, plus the new `LeagueFormat` enum's fixed value set and the `SocialLinkDto` nested array (reuse the existing `SocialLinkDto` schema already declared for `Sponsor`/`ClubProfile`, don't redeclare it).
9. **Required-by-standards unit tests, same PR**: extend `LeagueServiceImplTest.java` — `create`/`update` persist all five new fields; duplicate `socialLinks` platform within one request rejected (`400`); every new field stays optional (omit-all round-trips as null/empty).

### Frontend (`frontend-builder`, after backend types are settled)

1. **`ui/src/api/leagueApi.ts`** — add `LeagueFormat` union type (`'T20' | 'T30' | 'T45' | 'T50' | 'ONE_DAY' | 'THREE_DAY' | 'FIVE_DAY'`) and exported `LEAGUE_FORMAT_LABELS: Record<LeagueFormat, string>` (`ONE_DAY` → `'1 Day'`, etc.) so `LeagueForm`/`LeagueList`/`LeagueDetailPage` share one label source, never a second copy. Add `format`/`logoUrl`/`phone`/`website`/`email`/`socialLinks: SocialLink[]` (import `SocialLink` type from `../components/marketing/SocialLinksRow`, the same type `sponsorApi.ts` already reuses) to both `League` and `LeaguePayload` interfaces.
2. **`ui/src/components/LeagueForm/LeagueForm.tsx`** — restructure to mirror `SponsorForm.tsx`'s shape:
   - Root returns `<Box sx={{ gridColumn: '1 / -1' }}>` wrapping an MUI `Tabs` (`variant="scrollable"`, `scrollButtons="auto"`, `allowScrollButtonsMobile` — required by `docs/standards/frontend.md`'s mobile-first rule) with three tabs: **Basic Info** (default), **Branding**, **Social Media**.
   - `FormState` grows `format: LeagueFormat | ''`, `phone: string`, `website: string`, `email: string`, `logoUrl: string | null`, `socialLinks: SocialLink[]`, alongside the five existing fields.
   - Basic Info tab: existing `name`/`maxPlayingXiSize`/`minAge`/`maxAge`/`ageCutoffDate` Inputs, plus a new **Format** `Input select` (options from `LEAGUE_FORMAT_LABELS`, includes an empty/unset option), **Phone** `Input`, **Website** via `WebsiteInput`, **Email** `Input type="email"` (reuse `SponsorForm`'s `EMAIL_PATTERN`/`WEBSITE_PATTERN` client-side checks, format-only, optional).
   - Branding tab: single `MediaUpload` (`variant="logo"`, `namespace="manage"`) for `logoUrl` — no second upload for a banner (Non-goal).
   - Social Media tab: `SocialLinksFields` reused unchanged.
   - `toFormState`/`validate`/submit payload all extended; `blankToNull` helper added (mirrors `SponsorForm`) so clearing a field actually clears it.
3. **`ui/src/pages/manage/LeagueFormPage.tsx`** — the `initialValues` object passed to `<LeagueForm>` (line ~354-365) gains the five new fields from `league`. No other structural change — the outer Tabs (Details/Teams/Schedule/Playing Conditions) are untouched; `LeagueForm` renders at `activeTab === 0` exactly as today, now just rendering its own inner Tabs.
4. **`ui/src/pages/manage/LeagueList.tsx`**:
   - `LeagueCard`'s `avatar` gains `imageUrl: league.logoUrl` (MUI `Avatar` falls back to the existing `fallback` icon automatically when unset — no new logic).
   - Add `chips={league.format ? [LEAGUE_FORMAT_LABELS[league.format]] : undefined}` to the `<RecordCard>` call. Import `LEAGUE_FORMAT_LABELS` from `leagueApi.ts`.
5. **`ui/src/pages/manage/LeagueDetailPage.tsx`**:
   - Header `avatar` (line ~217) gains `imageUrl: league.logoUrl`.
   - Details section's `DetailFieldGrid` (after the existing `maxPlayingXiSize`/age-range rows, line ~254) gains `phone`/`email`/`website` `DetailFieldRow`s (`PhoneOutlinedIcon`/`EmailOutlinedIcon`/`LanguageOutlinedIcon`, each rendered only when set — mirror `SponsorDetailPage.tsx:79-82` exactly) and, when `league.socialLinks.length > 0`, a `<SocialLinksRow links={league.socialLinks} />` (import from `../../components/marketing/SocialLinksRow`, mirror `SponsorDetailPage.tsx:100`'s placement).
   - Details section object (line ~238-256) gains a `note:` field rendering a small `Chip` with `LEAGUE_FORMAT_LABELS[league.format]` when `league.format` is set — same `note` slot pattern the Playing Conditions/Fixtures sections already use, import `Chip` from `@mui/material`.
