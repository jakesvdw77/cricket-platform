# Plan 097: Import framework

Implements `docs/specs/097-import-framework.md` (approved 2026-10-10, open questions resolved with defaults). Plan only; the spec is not redefined. Covers Rollout slices 1 and 2 (backend, then UI). `098` (first consumer, slices 3 and 4) gets its own plan on the same branch (`feat/097-098-import-framework-and-schedule-import`), and is where the framework is declared done.

## Context
Clubs hold schedules, squads and sponsor lists in spreadsheets; every record is typed by hand. The spec defines one import flow (upload, parse, validate, resolve, confirm, commit, report, delete) with a server-enforced confirmation token, re-import safety by record identity, an "ours versus everything" scope option, and a guarded undo. This plan builds the generic backend and UI, proven by a test-only dummy handler, so `098` is a handler, a template and a matcher, not a new flow.

## Findings that adjust the spec's literals (to confirm)
1. **Migration number is 058**, not 041 (057 is the latest; register after the 057 include at line 64 of `db.changelog-master.xml`). File: `058-add-import-framework.sql`.
2. **No import code or libraries today.** Add Apache POI (`poi-ooxml`) and Apache Commons CSV to `backend/pom.xml` (approved by the spec, Open Question 6); pin versions at build time. The OWASP dependency check "added to CI" is a CI change: propose as a separate small item, not silently bundled.
3. **Token secret.** Spec fixes `app.imports.token-secret` (env supplied). `PublicAvailabilityToken` already shows the HMAC-SHA256, base64url, constant-time-compare pattern but is poll-specific (`PublicPollKind`) and falls back to a random per-process secret. Write a new `ImportConfirmationToken` in `service.support` copying the pattern; do not generalise the public one. A missing secret must fail startup in prod rather than fall back silently (flag: dev profile may use a fixed dev value).
4. **Advisory lock.** Only `SelectionLockRepository` exists (`pg_advisory_xact_lock(hashtext(...))`). Add `ImportLockRepository` in the same shape, key = hash of `clubId|type|scopeKey`.
5. **Scheduler.** `SchedulingConfig` already enables scheduling; the expiry job follows `AvailabilityAutoCloseServiceImpl` (`fixedDelayString` property).
6. **Exceptions.** Spec lists seven new named exceptions; two carry bodies (`ImportValidationFailedException` with `issues[]`, `ImportDeletionBlockedException` with `blockers[]`). `GlobalExceptionHandler` needs two dedicated handlers (pattern: `DuplicateFieldException`). `backend.md` already allows structured detail ("An exception may carry structured detail"), so the spec's promised amendment shrinks to adding the new exceptions to the matrix paragraph (no new base type or status). Note name clash risk: spec 104 already has `InvalidImportInputException`, `ImportInputValidationException` and `UnreadableImportInputException`; new `ImportFileRejectedException` must be distinct and not extend those.
7. **ArchUnit.** `ImportAdaptorRulesTest` covers `service.adaptor` only and asserts non-empty sets; keep the framework out of that package. New package use: `service.impl.ImportServiceImpl`, `service.support.*`, controller never touches repositories. Add an ArchUnit rule: only `ImportServiceImpl` may call an `ImportTypeHandler` (spec: "`ImportService` is the only caller of a handler"), proven non-vacuous with the test handler.
8. **Service signatures a handler calls (for `098`, informational here):** `MatchService.create(Authentication, clubId, req)` takes an `Authentication`; `LeagueTeamService.create(clubId, leagueId, seasonId, req)` does not. `ImportTypeHandler.commit` already receives `Authentication`, so no change.
9. **Test setup reusable:** `LeagueTeamControllerIntegrationTest.grantClubAdmin`, `PlatformRoleJwtPostProcessors`; a section manager is `CLUB_ADMIN` with `ScopeType.SECTION` (`AbstractLinkIntegrationTest`). Note: other club's admin on a club-scoped manage URL returns 403 from `canAdministerClub` in existing tests, while the spec says `404` for another club's `clubId`/batch. Plan: `403` from `@PreAuthorize` for a club the caller cannot administer (existing behaviour), `404` for a batch of the caller's club that does not exist or belongs to another club. **Flag back to the human:** spec acceptance says "another club's admin cannot preview...", and API says "a `clubId` that is not the caller's ... is `404`"; those two cannot both hold with `canAdministerClub`. Default: keep the repo's 403 for foreign `clubId`, 404 for foreign batch id.
10. **Multipart.** `MediaController` is image only and has no `@PreAuthorize`; import controller is club-scoped with `canAdministerClub`. Global 5 MB multipart limit is left alone; the 2 MB import limit is enforced in `ImportLimits` (spec).
11. **UI reuse.** An import wizard for match results already exists in `pages/manage/results/import/` (`importWizardTypes.ts`, `ConvertWithAiHelper`, `ImportProblemAlert`, `IMPORT_STEPS` as data) plus `components/WizardFooter`, `ResultStepper`, `DocumentUpload`. Build `ImportWizard` as generic `components/` and reuse `ConvertWithAiHelper`'s clipboard behaviour inside `ConvertWithAiPanel` (extend by props, do not copy). `CopyLeagueTeamsDialog` was not located by the research pass: confirm path before relying on it as the checklist pattern. League Schedule entry point (`LeagueEditScheduleTab`, Import button beside Share and Add match) belongs to `098`, not here.
12. **No dependency-cruiser config found** in `ui/` or the repo root; check `.github/` before assuming the `components/**` may not import `pages/**` rule is enforced (affects how `ImportWizard` stays generic).
13. **Claude Design pass required** before the UI slice for `ImportIssueTable`, `ReferenceResolver`, `ImportConfirmPanel` (spec; `docs/workflow.md` Step 2). Mockups shown to the owner before design changes, per standing rule. UI slice is blocked on that approval.

## Slices

### 1. Backend framework (backend-builder)
Order:
1. Migration `058-add-import-framework.sql` (`import_batch`, `import_batch_entity`, `import_alias`, indexes exactly as the spec) plus master include. Entities `ImportBatch`, `ImportBatchEntity`, `ImportAlias` in `domain`, repositories, `ddl-auto=validate`.
2. Enums and DTOs (flat, in `dto`): `ImportBatchDto`, `ImportRowDto`, `ImportIssueDto`, `ImportDecisionsDto`, `ReferenceProposalDto`, `PlannedChangeDto`, `DeletionCheckDto`, `DeletionBlockerDto`, `ImportTypeDto`; `ImportMapper` (MapStruct).
3. `service.support`: `ImportLimits` (2 MB, 1,000 rows, 1,000 chars, 5 and 20 open previews, 30 per hour, TTLs `IMPORT_PREVIEW_TTL` 24 h, `IMPORT_TOKEN_TTL` 30 min, `IMPORT_BATCH_RETENTION` 90 d), `ImportFileSniffer` (extension plus magic bytes, rejects `.xls .xlsm .xlsb`, zip-bomb guard via POI `ZipSecureFile`), `ImportConfirmationToken`, `ImportDigest` (canonical JSON SHA-256 of the effective import), `ImportTypeHandler` interface and supporting records (`ParsedImport`, `ValidationResult`, `EffectiveImport`, `PlannedChange`, `CommitOutcome`, `ExistingMatches`, `DeletionCheck`), `ImportHandlerRegistry` (bean map by `type()`), `ImportScope`/`TemplateScope`/`ScopeMode`.
4. Generic parse helpers used by every handler (one place): `XlsxTableReader` (POI: header row, merged region rejection, cell typing, formula result never formula, blank row drop, `_meta` sheet read) and `CsvTableReader` (Commons CSV, UTF-8 BOM, comma or semicolon sniff); workbook writer helpers for the template (Instructions, Lookups, hidden `_meta`, warn-only data validation). Handlers call these; the framework itself builds no real template.
5. `ImportService` + `ImportServiceImpl` (`@Transactional` on every read and write; only caller of a handler): types list, template, ai-help (reads `imports/prompts/<type>/v<templateVersion>.md`), preview (limits, whole-file re-import check by SHA-256 and rows hash), decisions (re-validate, bump `revision`, token only at zero errors and all warnings acknowledged), paginated rows with `status`/`outcome` filters applied in the query (rows live in `payload` jsonb, so the page is cut in the service from the stored payload; this is the one pagination shape R17 implies, state it in Javadoc so it is not mistaken for client-side paging), commit (token checks, creations digest, advisory lock, live re-validation including identity, single transaction, idempotent repeat, `409` with fresh state on change), discard, history, deletion-check, delete (all or nothing, only `CREATED` entities, revert updates from `previous`, FK violation mapped to `ImportDeletionBlockedException`, alias deactivation).
6. `ImportExpiryServiceImpl` (`@Scheduled`): `PREVIEW` past `expires_at` to `EXPIRED` with payload nulled; committed payload nulled 30 days after commit; metadata kept 90 days.
7. `ImportController` under `/api/v1/manage/clubs/{clubId}/imports` with `@PreAuthorize("@access.canAdministerClub(authentication, #clubId)")` on every method; multipart preview (`file` + `scope` JSON part + optional `timeZone`). Only the creator may change decisions or commit a `PREVIEW`; any club admin may view and delete a committed import (Open Question 4 default).
8. Exceptions (`ImportFileRejectedException`, `ImportValidationFailedException`, `ImportBatchNotFoundException`, `ImportBatchStateException`, `ImportBatchExpiredException`, `ImportConfirmationInvalidException`, `ImportDeletionBlockedException`) and the two `GlobalExceptionHandler` methods; extend the `backend.md` exceptions matrix (and the Imports rules) in the same PR.
9. Hand-edit `backend/openapi/openapi.yaml`, additions only (paths and the nine schemas).
10. Config: `app.imports.token-secret` in `application*.properties` (dev default only in the dev profile; env in prod; never logged), `app.imports.expiry.fixed-delay`.
11. `pom.xml`: POI and Commons CSV, pinned.
12. Test-only support in `src/test`: `DummyImportHandler` (creates simple records through a test table or an existing safe entity, with identity key, scope option and a registered blocker) registered only in a test configuration, never in main.

**Never run `mvn` in `backend/`**: rsync to a scratch copy; JDK 17 via `/usr/libexec/java_home -v 17`.

## Risks
Spec says "another club is 404" but `canAdministerClub` gives 403 (Finding 9). POI memory per request (limits and `ZipSecureFile` are the mitigation; 2 MB cap). Payload paging from jsonb is in-memory but bounded by 1,000 rows (documented exception). Token secret missing in prod must fail fast. Structural dependants test needs the FK catalogue query (information_schema) and must not be vacuous. Dependency cruiser may not exist, so layer purity relies on review. Name clash with spec 104 import exceptions. Time zone: preview takes an IANA `timeZone` (R11), included in the digest.
