## Context
The league page top row has five mixed buttons (Season pill, Share, Create match, Duplicate league, Edit), the Schedule tab scatters actions across the content line, and the league edit page's Schedule tab has yet another arrangement. This phase puts page-level actions in one place (Season pill, an Actions menu, a filled Edit league), each tab's actions on its own toolbar line, and turns the edit page's Schedule tab into a pointer. It follows the standard detail page and the owner's rules: no lone control in its own row, white-filled secondary buttons (already applied in `theme.ts`).

## Findings and decisions to flag (spec points that need a call)
1. **Add match must stay reachable.** The spec removes the header's Create match and replaces it with "Edit schedule" (Phase 2). Phase 1 would therefore leave the league page with no way to add a match. **Plan: the Schedule toolbar gets a filled "Add match" (link to the Match form with `leagueId` and `seasonId`, disabled without a season) as its one filled button; Phase 2 swaps it for Edit schedule.** Needs the owner's yes.
2. **Teams tab toolbar.** The spec and mockup show "Copy teams" and "Add league team" on a toolbar line, but today the Teams tab's actions live in each panel's header (Our teams: Add team; League teams: Add league team and Copy teams), which already follows the "inside the card it belongs to" density rule, and "Add team" has no place on a single toolbar. **Plan: leave the Teams tab as it is in Phase 1 (nothing moves) and note the deviation**; the owner can ask for the toolbar version later. Needs the owner's yes.
3. **Conditions toolbar.** Today: an optional secondary PDF button and a secondary Share; no filled button. **Plan: add a filled "Edit conditions" link (to the league edit page, Playing conditions tab, with the season) and keep PDF and Share as secondary.** The Conditions Share keeps preselecting CONDITIONS.
4. **Share from the top row** becomes the Actions menu item "Share league..." opening the same `ShareLeagueDialog` (preselect stays `['SCHEDULE']` as the header button does today).
5. **Import history.** `ImportsHistoryButton` owns its own panel and count. The Actions menu item needs the state in the layout: lift `open` and the count into a small hook (`useImportHistoryPanel`) in `pages/manage/leagueImport/`, used by the layout (menu item "Import history (n)" and the panel), and drop the "Imports (n)" text button from `LeagueScheduleView` and `LeagueEditScheduleTab`. `ImportScheduleControls.tsx` keeps `ImportScheduleButton`.
6. **Label.** The filled top button reads **Edit league** (it opens the existing edit page, tab and season carried as today). Tests that find the link by exact name `Edit` change; Playwright's `name: 'Edit'` is a substring match so the e2e clicks keep resolving.
7. **No shared header-actions component exists** (team and match pages build theirs inline; `MatchHeaderActions` is the nearest model). **Plan: add `components/ActionsMenu`** (four-file anatomy: component, test, story, index): a compact secondary "Actions" menu button with a caret on desktop, a 44 px bordered icon button (More, three dots) on a phone, items as data `{id, label, icon, onClick | to, disabled, reason}` with 44 px item height, keyboard and focus handled by MUI `Menu`, aria-label on the trigger. Do NOT refactor `MatchHeaderActions` or `QuickActions` now (listed as a later follow-up).
8. **Phone.** Top row: Back, then Season pill and the Actions icon button; Edit league is a full-width compact button under the title (the `CONTROL_SX` idea from `MatchHeaderActions`). Schedule toolbar on a phone: scope text, then the two buttons side by side.
