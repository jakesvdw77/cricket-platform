# Plan 066 — Poll Close Time and Unified Poll Cards

Implements `docs/specs/066-poll-close-time-and-unified-cards.md` (approved). Visual target: the design page https://claude.ai/artifact/2w92HN7t12sxyHecAMK3Y2 (icons there are approximate; real ones are MUI icons). Branch: `feature/066-poll-close-time-and-unified-cards` (off master, which already contains 064/065).

## Context

Managers cannot set or move a poll's close time, so a poll can't be extended and, after the time passes, can't be reopened (`064`'s rule). The two poll card kinds also look and behave differently and sit at different heights. Spec 066 adds an editable close time (at creation, afterwards, and as the way to reopen), one `PollCard` for both kinds built on the Summary-bar concept with the same four footer buttons, equal row heights, and manager corrections to answers on closed polls.

## Findings that shape the plan (gaps the spec left to the plan, and what exists)

1. **The group poll DTO has no exact first-kickoff time.** `SectionAvailabilityRoundDto` carries only `LocalDate`s (`firstMatchDate`/`lastMatchDate`, computed in the server's default zone), so the UI can't compute the default close time (kickoff − 24h, or − 1h) or the "not after first kickoff" check for a group poll. The server can: windows → `window_match` → `Match.matchDate` (the walk `getMatches()` already does). **A new `firstMatchKickoff` Instant is added to the round DTO** (additive; the spec doesn't list it).
2. **The spec's API table lists only the two new `PUT …/close-time` endpoints, but the creation screens must also send a chosen close time.** Plan: both create requests (`CreateSectionAvailabilityRoundRequest`, `CreateMatchAvailabilityPollRequest`) gain an optional `scheduledCloseAt`, validated by the same shared rule as the PUT (default stays kickoff − 24h when absent). This avoids a create-then-PUT two-step that could leave a poll with the wrong close time if the second call fails. (Additive, flagged below.)
3. **The "closed poll" check on the admin override is separate from the public check**, so removing it is safe: squad `MatchAvailabilityPollServiceImpl.setPlayerStatus` (L241-243, `PollClosedException`) and group `SectionAvailabilityRoundServiceImpl.setPlayerStatus` (L404-407, per-window `SectionAvailabilityWindowClosedException`). `PublicAvailabilityPollServiceImpl` (L92-93) and `PublicSectionAvailabilityRoundServiceImpl` (L90-92) keep their own checks untouched.
4. **There is no `Clock`**; production uses `Instant.now()` and tests use margins. "In the future" validation follows that style (no new Clock bean).
5. **The reopen rule from `064` (`AutoCloseSchedule.canReopen`) stays unchanged** at the API; the UI satisfies it by saving a future close time first, then opening. The scheduler's `findDueForAutoClose` already ignores closed polls and tolerates future edits.
6. **Why heights differ today:** `GroupPollCard` wraps `RecordCard` in a flex `Box` (so `height: 100%` has no definite parent) and has in-card Collapse panels; `SquadPollCard` returns the card itself. Fix: one `PollCard` returns the `RecordCard` as the grid item, expansions become dialogs, grid `alignItems: stretch`.
7. **`RecordCard` can't do the design's footer** (four equal columns, icon over caption) or a custom body: it has only wrapping ghost buttons and `fields`. It needs two additive slots: a `children` body slot and a `footerButtons` layout.
8. The summary bar/legend is inline in `ResponsesSummary.tsx`; the card needs it too, so it is extracted to a shared **`components/SlotSummary`** (four-file anatomy, per `frontend.md`) and `ResponsesSummary` uses it.
9. There is **no client helper deriving MORNING/AFTERNOON from a Date** (needed for the squad card's one slot), and `toDatetimeLocal`/`fromDatetimeLocal` are private to `MatchForm`. Both become shared utils.
10. `PollShareDialog` takes a full `Match` but only reads `matchDate`, `venue` and the team names; its prop type is narrowed (`Pick<Match,…>`) so the squad card can use it without fetching the match.

## Part 1 — Backend (`backend-builder`; build/test ONLY in an rsync'd scratch copy, never in `backend/` — the live IntelliJ backend runs from `backend/target/classes`)

**B1. Shared validation.** `AutoCloseSchedule` (service/support) gains `validateCloseTime(autoClose, scheduledCloseAt, earliestKickoff, now)` → `InvalidCloseTimeException extends ValidationException` (400; named subclass per `backend.md`): `autoClose=false` stores null (any supplied time ignored); `autoClose=true` requires a non-null time; the time must be after `now`; and not after the earliest kickoff. Unit tests for every branch.
**B2. Endpoints.** New request `UpdatePollCloseTimeRequest(boolean autoClose, Instant scheduledCloseAt)`; `PUT /api/v1/manage/clubs/{clubId}/matches/{matchId}/polls/{pollId}/close-time` (squad: `findMatchOrThrowForClub` → `assertCanAdministerMatch` → `findPollOrThrowForMatch` → validate against `match.getMatchDate()` → save; returns `MatchAvailabilityPollDto`) and `PUT …/section-availability-rounds/{roundId}/close-time` (group: `findRoundOrThrowForClub` → `assertCanAdministerSection` → validate against the earliest kickoff, recomputed via the windows→`window_match`→`Match` walk, extracted from `getMatches()` into one private helper reused for the DTO field → save; returns `SectionAvailabilityRoundDto`). `@PreAuthorize canAccessClub` like siblings, `@Transactional`; works on open and closed polls and does not change `open`.
**B3. Create requests** gain optional `scheduledCloseAt`, validated by the same helper (absent = default kickoff − 24h as today). **`SectionAvailabilityRoundDto`** gains `firstMatchKickoff` (Instant).
**B4. Admin override on closed polls:** delete the two admin-side closed checks (finding 3); the public endpoints and their tests stay.
**B5. OpenAPI:** regenerate `backend/openapi/openapi.yaml` from a throwaway Testcontainers `@SpringBootTest` in the scratch copy (fetch `/v3/api-docs.yaml`, `sed` the server URL to `http://localhost:8082`); review the diff is only the intended changes.
**Tests (builder writes; `test-writer` fills gaps):** the existing tests that assert the old closed-override rejection are flipped (`MatchAvailabilityPollServiceImplTest.setPlayerStatusRejectsAWriteAgainstAClosedPoll`, `SectionAvailabilityRoundServiceImplTest.setPlayerStatusRejectsAWriteAgainstAClosedBracket`, `MatchAvailabilityPollControllerIntegrationTest.setPlayerStatusReturns409WhenThePollIsClosed`, the combined case in `SectionAvailabilityRoundControllerIntegrationTest`); the public tests stay green unchanged. New: validator branches; both PUTs (valid save, autoClose false clears, past `400`, after-kickoff `400`, autoClose true without time `400`, closed poll stays closed, edit-then-reopen succeeds, section-scope `403`/`404`, cross-club `404`); create with and without `scheduledCloseAt`; `firstMatchKickoff` populated; override accepted on closed for both kinds while public stays `409`.

## Part 2 — Frontend (`frontend-builder`, in parallel with Part 1; all under `ui/`; `source ~/.nvm/nvm.sh && nvm use 22.12.0` before any npm)

**F1. Shared utils.** `utils/datetimeLocal.ts` (lift `toDatetimeLocal`/`fromDatetimeLocal` out of `MatchForm.tsx`, which imports them); `utils/dayPart.ts` gains `dayPartForDate(date)` matching the backend resolver's rule and zone (the builder must read `SectionAvailabilityMatchResolverImpl` first and mirror it exactly, including time zone); `pollHelpers.ts` gains the default close-time helper (kickoff − 24h, else − 1h when that is already past) and an `isValidCloseTime` mirror of the server rules for inline messages. Tests for each.
**F2. `components/SlotSummary/`** (four files; story + test): heading, stacked bar, text legend, "N of M answered", `data-testid`s as today. `ResponsesSummary` (065) is refactored onto it.
**F3. `RecordCard` additive slots:** `children` (rendered in the body between fields and feedback) and `footerButtons?: { label, ariaLabel?, icon, onClick, disabled? }[]` rendering four equal columns, icon over a short caption (never clipped or wrapped); all existing props/behaviour unchanged. Tests + stories (incl. a narrow-width story).
**F4. Unified card.** New `pages/manage/availability/PollCard.tsx` taking a normalised item (`{kind: 'SQUAD'|'GROUP', …}`) replaces `SquadPollCard.tsx` and `GroupPollCard.tsx` (deleted): header (avatar, title; group has the description pencil opening a small dialog instead of the old inline panel, badges Squad/Group poll + Open/Closed + Home/Away, bin top-right), subtitle (group: "Section · N matches"; squad: `formatMatchDateTime` · venue), one `SlotSummary` per slot (group: `round.brackets`; squad: one slot from `matchDate` + `dayPartForDate` + counts), a "Closes <date time>" / "Closes manually" / "Closed <date>" row with a pencil, footer `footerButtons` in fixed order **Close (Reopen… when closed) · Matches · Responses · Share**. Dialogs as siblings (no wrapper `Box`): existing close/delete `ConfirmDialog`s (group delete 409 acknowledge-only kept), new page-local `PollMatchesDialog` (group: `getRoundMatches` grouped per slot; squad: its one match with the existing link), `SectionAvailabilityShareDialog` / `PollShareDialog` (prop type narrowed), and `EditCloseTimeDialog`. Responses goes to `/manage/availability/group/:id` (group) or the match Availability tab link (squad). `AvailabilityPollsDashboard`: grid `alignItems: 'stretch'`, passes normalised items, `invalidatePolls` unchanged.
**F5. `EditCloseTimeDialog`** (page-local, used by the card, the Responses page header and `MatchFormPage`): Autoclose `Switch` + shared `Input type="datetime-local"` (via F1), pre-filled with the current close time or the default; inline errors per the server rules; **Save** calls the new `updateRoundCloseTime`/`updatePollCloseTime`; on a closed poll the title is **Reopen** and the primary action saves the time then calls `openRound`/`openPoll`; invalidates the dashboard prefixes plus the Responses page's `detail`/`responses` keys; server 400/409 text via `errorDetail`.
**F6. Creation screens.** `FixtureGroupCard` and `SquadPollBranch`: replace the read-only "closes …" text with an editable "Closes at" field (group: one per card; squad: one per ticked match row) defaulting per F1 beside the Autoclose switch; `createRound`/`createPoll` send `scheduledCloseAt`. API files get the new fields, the two PUT functions, and `firstMatchKickoff` on the round type.
**F7. Closed-poll corrections.** `GroupPollResponsesPage`: header "Closes …" gets the pencil/`EditCloseTimeDialog`; the closed note becomes "This poll is closed. Changes are recorded as a manager correction."; `override.disabled` is removed. `MatchAvailabilityTab`: status chips enabled when closed, closed alert text updated, the reopen switch replaced by a **Reopen…** button that asks `MatchFormPage` to open `EditCloseTimeDialog`; its create-time Autoclose switch keeps the default rule.
**Tests:** rewrite/extend `AvailabilityPollsDashboard.test.tsx`, `NewPollPage.test.tsx`, `GroupPollResponsesPage.test.tsx`, `MatchAvailabilityTab.test.tsx`, `MatchFormPage.test.tsx`, `RecordCard.test.tsx`; new tests for `SlotSummary`, `PollCard` (both kinds: header, subtitle format, slot summaries and bar widths, closes row, identical footer buttons and order, closed variant), `PollMatchesDialog`, `EditCloseTimeDialog` (default, validation, payload, autoClose off, Reopen path), the utils; no arbitrary timeouts.

## Flags for your review

1. **New `firstMatchKickoff` field on the group poll DTO** (not in the spec) — required for the close-time default and validation on the UI side.
2. **Create requests get an optional `scheduledCloseAt`** (the spec's API table only lists the two PUTs) — avoids a two-step create that can fail halfway.
3. **The client `dayPartForDate` must match the backend's Morning/Afternoon rule and time zone**; the builder is told to read the resolver and mirror it.
4. **Group description editing moves from an in-card panel to a small dialog**, so cards never change height on their own.
5. **No `open` flag is added to the squad poll DTO**; open/closed still comes from which list the poll arrived in.
6. **`MatchFormPage`/`MatchAvailabilityTab` get a small Reopen… flow** so the squad poll's own tab can reopen via the new dialog (otherwise a closed squad poll past its close time could only be reopened from the dashboard).
7. **"In the future" validation uses `Instant.now()`** (no `Clock` bean exists); tests use margins.
8. Playwright is not extended (no live services here), as with 064/065.
