# Plan: 115 Player match list (a "Matches" tab on the player stats page)

Spec: `docs/specs/115-player-match-list.md` (branch `feature/115-player-match-list`, mockups approved, working answers to Q1-Q14 recorded in its "Decisions of 2026-10-20"). Builds on spec 103 as merged. Compute on read, **no migration, no table, no index**, manager-only.

## Context

Spec 103 gives totals and boards but no way to walk back through a player's games. This adds a fifth tab, **Matches**, to `/manage/players/:playerId/stats`: one row per counted match, newest first, with the player's own batting/bowling/fielding figures, the result from the player's side, the opponent, awards, paging (Show more), and a way into the result page and back. Counting rules, filters and access are exactly 103's and live once in `PlayerStatsSql.APPEARANCES`.

## Spec points the plan follows, and small things the code research settled (no owner decision needed)

- `size` above 100 is a **400** (spec 115), unlike the leaderboard which silently clamps: copy only the `page < 0` and `size < 1` checks from `LeaderboardServiceImpl`, define new constants (default 20, max 100); the leaderboard constants are package-private.
- **Opponent name** (spec said "plan confirms the fields"): `coalesce(team.name, match.<side>_team_name)` for the opposite side. A league team's name is already copied into `match.*_team_name` on write, so no `league_team` join. Our team name: `team.name` of the player's own side (club id checked). Same precedence the UI helper `matchCardHelpers.sideName` uses. A derby has `opponentName = null`.
- **Dismissal wording:** spec/mockup show lowercase words ("caught", "lbw"); `utils/dismissal.ts` has capitalised labels. Use `dismissalLabel(type).toLowerCase()` with "LBW" lower-cased as "lbw", in a small formatter in the tab, so the shared helper is untouched.
- **Dates:** no existing helper formats an ISO instant as "14 Mar 2026" (`formatDateOfBirth` is date-only). Add one tiny formatter with the same `en-GB` options.
- `ResultDetailPage` reads no router state today and hard-codes "Back to Results" in three places; only the header link (and its two error-state actions) change, guarded by `backTo.startsWith('/manage/')`.
- `PlayerStatsPage` does not read `competition` from the address; add it next to the other four leaderboard link params (spec requires it).
- The totals row is fed from the `PlayerStats` the page already loads: no new endpoint.
- `PlayerMatchRowBuilder` must take its own plain input records (like `PlayerStatsFacts`), not repository projections, or the pure-class ArchUnit rule fails; a small adapter (like `PlayerStatsCountersReader`) maps projections to inputs.
- **Likely existing e2e bug to fix in the tests slice:** `manager-player-stats.spec.ts` `firstBoardPlayerId` reads `href` off a `role="row"` Box that is no longer a link (the standings row became a Box with an inner link). Fix when the e2e is touched.
- Spec 115 needs no change before building; nothing contradicts it. (If the owner changes a Q answer later, the spec is updated first.)

## Backend (backend-builder). `backend/src/main/java/com/cricketlegend/`

1. `repository/PlayerStatsSql.java`: extract the `has_bat` / `has_bowl` exists-expressions and the "valid balls" expression into shared constants used by the AGGREGATE `app`/`bi` CTEs, `recentInnings` and `bestInnings` (a pure refactor; proven by `PlayerStatsSqlLiteralsTest` (add the new constants to its `allSql()` list so the literal checks see them) and the parity test). `APPEARANCES` is unchanged.
2. `repository/PlayerStatsFactsRepository.java` (stays the only reader; no new repository, so no new `ownersRegex` entry): add native queries on `APPEARANCES`, all with its eight parameters, projections with quoted camelCase aliases, dates as epoch millis:
   - `matchCount` (`count(distinct mrid)`), and `matchPage` (one row per `mrid`: match id, result id, epoch millis, `derby`, outcome, winning side, `bpo`, league id/name, our team id/name per side the player appears on, opponent name, the two card flags via the shared constants; `order by match_date desc, match_id desc limit/offset`, direction flipped for asc);
   - three entry queries for exactly the page's `mrid`s: the player's counted batting rows (innings, runs, balls with the valid-balls rule, fours, sixes, how_out, not-out), bowling rows (balls, maidens, runs, wickets, dots, wides, no_balls), and fielding sums + award counts (`PLAYER_OF_MATCH`, `TEAM_PLAYER_OF_MATCH`), each reached only through `ap.rpid` and `REGULAR` innings. Four-to-six statements per page, none per row (a query-count test pins it).
3. `service/support/` (pure): `PlayerMatchRowBuilder` plus input records (`MatchHeader`, `BattingFact`, `BowlingFact`, `FieldingFact`, `AwardFact`) and the row output records or reuse of DTO parts, deciding statuses (`NO_CARD`, `DID_NOT_BAT`/`DID_NOT_BOWL`, `BATTED`/`BOWLED`/`RECORDED`), the result from the player's side (derby = `INTERNAL`, no-result/abandoned reported as such), multi-innings `innings[]`/`spells[]` plus sums, the coverage rule for `balls`, and a derby row combining both sides' figures. A small adapter class maps projections to the input records.
4. `service/`: `PlayerMatchListService` + `service/impl/PlayerMatchListServiceImpl` (`@Transactional(readOnly = true)`): validate `page`/`size`/`direction`, `parseCompetition` (reuse the rule from `PlayerStatsServiceImpl`, extract it to a shared helper if it avoids duplication), 404 for an unknown/other-club player, `StatsScopeResolver.resolve(...)` (called, not copied; empty reach → empty page 200), repository, builder; names never logged.
5. `dto/`: `PlayerMatchListDto` (`playerId`, `scope` reusing `PlayerStatsDto.PlayerStatsScope`, `page` reusing `LeaderboardTableDto.LeaderboardPageInfo`, `rows[]`) and `PlayerMatchRowDto` with nested `PlayerMatch*` records per the spec's table (prefix nested names to avoid springdoc collisions).
6. `controller/PlayerStatsController`: add `GET /players/{playerId}/stats/matches?seasonId&leagueId&teamId&sectionId&competition&direction&page&size`, same `canAccessClub` guard, `Integer page/size`, `String direction`.
7. `LayeringRulesTest` edits (mandatory): add `PlayerMatchListServiceImpl` and the adapter class to `STATS_SERVICES`; extend `theStatsRepositoryUsersAreExactlyWhoWeExpect`; add `PlayerMatchRowBuilder` and its nested types to `PURE_STATS_CLASSES` and update the `thePureStatsClassesExist` count (32 today) to the new exact total.
8. `backend/openapi/openapi.yaml`: new path after the filter-options path (unique `operationId` e.g. `getPlayerMatches`), schemas reusing `PlayerStatsScope` and `LeaderboardPageInfo`, 400/403/404 responses like the stats route.

## Frontend (frontend-builder). `ui/src/`

2. `pages/manage/playerStats/playerStatsTabConfig.ts`: add `{ value: 'matches', label: 'Matches' }` last.
3. `PlayerStatsPage.tsx`: read `competition` from the address once (like the other link params), render `MatchesTab` for `?tab=matches`, build the `backTo` URL (`?tab=matches&seasonId=&leagueId=&teamId=&sectionId=&competition=`), `?dir=asc` handling; basis line already works (falls through to the plain wording).
4. `MatchesTab.tsx`, `MatchRow.tsx`, `MatchCard.tsx` (page parts, no four-file anatomy): desktop table in the `StandingsTable` look (role=table/row/columnheader/rowheader/cell, 36 px header, 40 px rows, 14 px cells, `zebraTint`/`hoverTint`, focus ring, Date heading a button with `aria-sort` that reverses); columns Date, Opponent (+ our team sub-line; "Internal match" for a derby), Competition, Result badge (`badgeSx`, text + dot), Runs/Balls/How out, Bowling cell ("2/21" + "4.0 ov · 1 mdn · 8 dots" via `oversFormat`), Fielding cell, Awards marker; pinned Total row from `PlayerStats`; phone: stacked cards with the Total card first; statuses render "Did not bat/bowl" muted, a missing card as a dash, an all-NO_CARD match as one "No scorecard captured" note; "Showing N of M matches" and a 44 px outlined Show more; loading skeletons, error with Try again, empty states through the page's existing handling. 5. `pages/manage/results/ResultDetailPage.tsx`: read `useLocation().state`; if valid (`backTo` starts with `/manage/`) the header link and the two error-state actions read "Back to <label>" and go to `backTo`, otherwise unchanged.
6. A tiny date formatter util (en-GB, day numeric, month short, year numeric, from an ISO instant) and a how-out lowercase helper; reuse `dismissalLabel`, `oversFormat`, `badgeSx`, `zebraTint`, `hoverTint`, `resultViewTo`, `StatTile` parts. No new shared component, no new filter UI.
7. Keep existing tests green: add `usePlayerMatches` to the `PlayerStatsPage.test.tsx` mock factory (otherwise tab tests break), and the `?competition=` case.
