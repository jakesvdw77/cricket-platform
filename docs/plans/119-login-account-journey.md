## Order, verification, risks

Slices ship sequentially, each looked at before the next starts; in slice 3 the nav rename and Access shell start without backend, frontend conforms to DTOs as they land (the 116 pattern); backend 3A-3C is largely sequential; slice 4's two halves run in parallel. Verification: backend in a scratch copy (compile, `LayeringRulesTest`, `PublicAvailability*` unchanged, integration tests, OpenAPI diff); frontend `npm run lint`, `npm run build`, vitest on touched folders only; manual full parent journey on a local Keycloak with the mail sink after running the data checks. Risks: Keycloak version coupling of the theme (re-run the checklist on any upgrade); Google OAuth client per environment and the production realm name; the first-broker-login flow is manual and easy to misconfigure; the under-18 `bridgeByEmail` amendment to 016 can affect existing rows (the data check sizes it); the 077 refactor (keep its tests unchanged); section-scoped managers cannot enter `/manage` today; realm drift because the container has no volume (export first); email is the owner's Google SMTP (testing only).
